# Python 编程教学工具发布手册

## 范围与前提

本手册描述第 5 阶段的人工发布流程。发布前必须通过本地质量检查，并由部署人员明确确认目标目录、反向代理位置、后端环境变量和备份位置。本仓库不会保存任何生产密钥。

当前已验证的隔离执行器运行在服务器回环地址 `127.0.0.1:5182`。后端调用执行器时也只能使用该回环地址；不要把执行器端口暴露到公网。

## 本地发布材料

在仓库根目录执行：

```powershell
npm ci
npm test
npm run check
npm run build
npm run preflight
npm run package:release
git diff --check
```

`release/manifest.json` 记录每个发布文件的路径、大小和 SHA-256；`release/SHA256SUMS` 供传输后复核。它包含前端构建产物、前端组织器依赖、后端源码、执行器源码、发布手册和根依赖锁文件。

## 传输与复核

1. 将发布文件与 `release/SHA256SUMS` 传输到一个新的、带版本号的服务器目录；不要覆盖现有运行目录。
2. 在服务器目标目录运行 `sha256sum -c SHA256SUMS`，确认全部文件为 `OK`。
3. 先以不接入反向代理的方式启动后端，并仅通过本机回环地址检查其健康接口与执行器连接。
4. 再把前端静态文件切换到反向代理的候选目录，检查 `/teaching-python/` 的页面资源、API 代理、教师只读视图和一次 Python 运行。

## 上线门槛

切换流量前必须同时满足：

- 后端不直接执行学生代码，所有运行都经由隔离执行器。
- 执行器仍只监听 `127.0.0.1:5182`，容器限制与无网络策略未被放宽。
- 前端页面、后端健康检查、项目保存、运行轮询、教师班级查看、分发与学生副本均完成冒烟检查。
- 当前生产目录、服务单元文件和反向代理配置已有可恢复备份。

## 回滚

若上线后任一健康检查失败，立即停止切换而不是在生产目录直接修补：

1. 将反向代理恢复到先前的前端目录，并重新加载反向代理配置。
2. 将后端服务恢复到原先的版本目录并重启该服务。
3. 不修改已验证的执行器服务及其环境文件；只有执行器变更本身造成故障时，才恢复到保留的上一版应用目录。
4. 复查前端页面、后端健康接口和执行器 `/health`，记录失败版本与日志位置。

执行器目前保留有服务器端旧应用目录作为恢复点。不要删除旧目录、镜像导入包或服务日志，直至全量上线稳定后再按单独确认的清理计划处理。
